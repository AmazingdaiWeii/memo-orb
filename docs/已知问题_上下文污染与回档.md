# 已知问题：上下文被污染之后，「回档」为什么不能只做一半

> 适用版本：2026-10-23 起带「冻结记忆 / 唤醒记忆」的版本。
> 这份文档讲的是**出问题时怎么救**，不是功能说明。功能说明见同目录的 [2026-10-23 功能更新说明](2026-10-23功能更新说明.md)。

---

## 先说结论

「唤醒记忆」把**磁盘上的文件**恢复到你冻结的那一刻。
但它不会、也没法清理**正在运行的那一份上下文**。

所以如果此刻上下文已经被污染（她开始引用没发生过的事、伪造你的话、把假事实当已知），
**只点一下「唤醒记忆」是救不回来的** —— 甚至会更糟。

正确的做法有两种，取决于你想干什么：

- **换机器 / 彻底重来** → 见第三节。**不要启动应用之后再唤醒，要在启动之前把文件铺好。**
- **同一台机器回到更早的时间点** → 见第四节。**唤醒之后立刻退出并重开，中间一个字都不要说。**

---

## 一、回档能修什么、修不了什么

| 东西 | 存在哪里 | 回档能修吗 |
|---|---|---|
| 记忆文件（含 git 历史） | `data/memfs/` | ✅ |
| 对话原文 | `data/conversations/*/messages.jsonl` | ✅ |
| 系统提示词快照 | `data/conversations/*/system.json` | ⚠️ 能恢复文件，但**会被原样复用**（见第三节坑 2） |
| 压缩摘要 | 就在 `system.json` 里面 | ❌ 它是改写过的历史，原始来源不可追 |
| 进程里正在跑的上下文 | 内存 | ❌ 换文件清不掉 |
| 这一轮已经发出去的请求 | 网络 | ❌ 发出去就收不回 |
| 她已经做过的事（评论、私信、投币） | 站外 | ❌ 永久 |

一句话：**回档修的是"存档"，修不了"经历"。**

---

## 二、最危险的一幕：回档被自己的运行覆盖了

这是这个功能真正的缺陷，也是这份文档存在的原因。

```
你点了唤醒 → 文件被换成冻结点那一版（干净）
     ↓
应用还在跑，她手里端着**旧的上下文**（污染还在）
     ↓
你接着说了一句话
     ↓
她带着污染的历史回了一句 → 这句话被追加写进刚恢复的 messages.jsonl
     ↓
结果：干净的历史 + 一条从污染里长出来的新消息
```

**第二回合你就看不出回档发生过。** 文件时间是对的、内容也是"连续的"，
但那条新消息是从污染里长出来的，而它现在已经变成了新的"事实"。

所以：回档之后**在重启之前，一句话都不要说**。这不是建议，是必要条件。

## 三、换机器 / 彻底重来的正确顺序

适用于：换了电脑、系统重装、或者污染严重到不想在同一台机器上冒险。

**全程不要启动新装的应用。** 顺序错了就白做。

### 第 1 步：先找到一个东西 —— 原来的 agentId

打开你那份存档，看这两个地方之一：

- `manifest.json` 里的 `meta.agentId`（推荐，最准）
- 存档里 `memfs/` 下面那个目录的名字（比如 `orb-20250101`），它就是 agentId

记住它，下一步要用。

> ⚠️ **坑 1：agentId 不在存档的恢复范围里。**
> 出厂版的 `config.json` 里 `agentId` 是 `null`，启动后会落到默认值 `local-agent`。
> 而你的记忆在 `memfs/orb-20250101/`。
> 如果你直接铺文件就启动，它会去找 `memfs/local-agent/memory` —— **那里什么都没有**，
> 于是她表现得像失忆，而你会以为存档坏了。**这一步不做，后面全白做。**

### 第 2 步：把新装的 `config.json` 里的 agentId 改成上面那个

用记事本打开新装目录里的 `config.json`，找到 `"agentId"`，把值改成第 1 步记下的那个。

改完是类似这样：

```json
"agentId": "orb-20250101"
```

> 如果原来是 `null`，就整个值换成字符串。**不要**只改 `memfs/` 的目录名去迁就它 ——
> 对话目录名里也编着 agentId，改一处不改另一处只会更乱。

### 第 3 步：把存档铺进 `data/`

把存档里这几样复制进新装目录的 `data/`（覆盖同名）：

- `memfs/` —— 记忆仓，**必须连里面的 `.git` 一起拷**，否则历史就断了
- `conversations/` —— 对话原文
- `policy.json`、`schedule.json`、`bili-history.json` —— 如果你也要带过来

存档里**没有** API Key、B 站 cookie、微信配对。这些要重新填 / 重新扫码，是故意的。

### 第 4 步（关键，最容易漏）：删掉 `system.json`

删掉 `data/conversations/*/system.json`（每个对话目录下都有一个）。

> ⚠️ **坑 2：`system.json` 会被原样复用，不会重新编译。**
> 程序启动时先读这个文件，只要"工具指南版本"和"人格指纹"没变，就**直接拿来用**，
> 不会去看你恢复的记忆。而它里面装着两样要命的东西：
>
> - **记忆正文的副本**（常驻那部分每轮全文注入，副本就在里面）—— 污染在这，就还在
> - **压缩摘要**（`## 更早的对话摘要`）—— 它是改写过的历史，可能已经把污染吸收了
>
> 删掉它之后，程序会在启动时**从你恢复的记忆现场重新生成**一份干净的。
> 代价是那份压缩摘要会丢 —— 但那正是应该丢的东西。

### 第 5 步：现在才启动

启动后她读到的就是恢复后的记忆，上下文是从干净文件现场编译出来的，
不存在"旧上下文还在内存里"的问题。**这是唯一一个不需要重启就生效的路径。**

### 第 6 步：重新填 Key / 登录

模型 API Key、B 站扫码、微信配对，都在设置里重来一遍。

## 四、同一台机器上回到更早的时间点

适用于：数据还在，只是想退回去。

1. **先把现在冻结一份**，哪怕它是脏的。理由见第六节。
2. 点「唤醒记忆」，选一份存档。确认之后它会先自动给"现在"也存一份。
3. **唤醒一结束，立刻退出应用，然后重开。**
4. 重开之前，把第 3 节第 4 步那件事也做一遍：如果新恢复的 `system.json` 是旧的，
   删掉它（否则提示词还是旧的那一份）。

> 如果你只是想"把记忆退回去、不想动对话原文"，
> 这条路仍然会留下旧上下文 —— 因为 `system.json` 里印着旧记忆。
> 所以**还是得删 system.json 或重开**。这就是第二节说的那个缺陷。

## 五、这套办法救不了什么

**1. 冻结点之前就已经被污染的，救不回来。**
回档只能回到"你冻结的那一刻"。如果那一刻已经是脏的，回档就是把脏的再装一遍。
判断方法：打开存档里的 `memfs/*/memory/MEMORY.md`，看有没有你不认识的内容。

**2. 已经被压缩进摘要的污染，救不回来。**
摘要是一份改写过的历史，原文已经被丢掉了。所以删 `system.json` 是必须的 —— 那是唯一能丢掉它的方式。

**3. 她已经对外做过的事，撤不回。**
发出去的评论、私信、投币，回档后她的历史里没有这些事。下次你提起来，她会真诚地否认。
**这不是她坏了，是回档必然的代价。** 提前知道这一点，比事后以为是 bug 好。

---

## 六、你会失去什么（默认预期）

恢复之后，她**不会记得冻结点之后发生的任何事**。

那些事在你的存档里、在你的记忆里，但在她那边的索引里不存在，
所以不会被注入对话 —— 她不是"想不起来"，是"从来没发生过"。

如果你希望那些事将来还能捞回来：

> **在救援之前，先冻结一份当前的（脏的）状态。**

那份脏存档里装着冻结点之后的**全部真实经历**。它现在不能用，
但等你有空的时候，可以手工从里面挑出真的事实补回记忆仓
（脏的是那几条被伪造的，不是全部）。

---

## 七、一句话备忘

- 回档 = 换文件。**换文件不会自动换掉正在跑的上下文。**
- 换机器救援：**先改 agentId，再删 system.json，最后才启动。**
- 同机回档：**唤醒之后一句话都别说，直接退出重开。**
- 冻结点之后的事，默认当作没发生过。

## 附录 A · 交给 agent 执行的流程

> **怎么用**：把这一节整段复制给一个能读写文件、能执行命令的 agent（DeepSeek Harness / Claude Code / Codex 等），
> 连同 A.1 的三个路径一起给它。它面向的是**没有本项目上下文的执行者**，所以每一步都带「期望」和「不符就停」。
>
> 如果你愿意自己动手，照第三节走就行，不需要这个附录。

### A.0 硬约束（任何一条都不要自行放宽）

**允许**：读文件、复制文件、改 `config.json` 里的一个字段、建备份目录、算文件哈希、移动文件到隔离目录。

**禁止**：

1. **不许删除任何原始数据。** 要「删掉」的东西一律先**移动**进 `quarantine-<stamp>/`。
2. **不许启动 `Orb.exe` 或任何 GUI。** 启动由人做 —— agent 启 GUI 会挂住，会被误判成卡死。
3. **不许碰 `data/providers/`、`bili-auth.json`、`wechat.json`、`wechat-state.json`。** 这些是凭据，存档里本来就没有，也不要从旧目录搬过去。
4. **不许在任何地方跑 `tsdown` 或构建脚本。** `helper/lib/main.js` 是构建产物，而 `helper-src/src/main.ts` 是一份不完整的源，重建会把功能连根拔掉。
5. **不许猜 `agentId`。** 找不到就停下来报告，不要用默认值兜。
6. **不许在完成步骤 1 之前覆盖或移动用户的 `data` 目录。**

### A.1 需要人提供的三个路径

| 代号 | 是什么 | 例子 |
|---|---|---|
| `OLD` | 现在这个（已污染 / 要退役的）安装目录 | `D:\Orb` |
| `NEW` | 新解压出来的出厂版目录 | `E:\Orb-new` |
| `SNAP` | 存档目录（里面有 `manifest.json` 和 `说明.txt`） | `D:\备份\orb-20250101-1530` |

缺任何一个都不要开始。

### A.2 先判定是哪一种情况

- `NEW/data/memfs/` 存在且非空 → **同机回档**，跳到附录 B。
- 否则 → **换机救援**，走 A.3。

### A.3 换机救援（逐步，每步看「期望」，不符就停）

**步骤 1 · 备份，不动原件**

- 做：把 `OLD/data` 整个复制到 `OLD/../orb-rescue-backup-<yyyymmdd-HHmm>/data`
- 期望：新目录下 `memfs/`、`conversations/` 都在
- 这一步没做完，不许往下

**步骤 2 · 校验存档完整性**

- 做：跑附录 C 的脚本，`<SNAP>` 当参数
- 期望输出：`OK <n> files`
- 输出里有 `MISSING` / `SIZE` / `HASH` → **停**，告诉人「存档不完整，先找回完整副本」
- 为什么：文件夹形态的存档可能只拷了一半，而少一个文件的表现是「她丢了某段记忆」，不是报错

**步骤 3 · 取 agentId**

- 做：读 `<SNAP>/manifest.json` 里的 `meta.agentId`
- 如果它是空的：读 `<SNAP>/memfs/` 下**唯一那个子目录**的名字，那就是 agentId
- 两个都拿不到 → **停**

**步骤 4 · 对齐 `config.json`**

- 做：读 `<NEW>/config.json`，只把 `agentId` 改成步骤 3 的值，写回（其它字段不要动，不要重排格式）
- 期望：读回来能打印出那个值，且其它字段原样
- 注意：原本是 `null` 的话，要改成字符串
- 为什么：出厂版的 `agentId` 是 `null`，启动会落到默认值 `local-agent`；而存档里的记忆在 `memfs/<旧 id>/`。不改这一步，铺完之后**她找不到自己的记忆，表现成失忆**

**步骤 5 · 铺存档**

- 做：把 `<SNAP>/` 里的这些复制进 `<NEW>/data/`（覆盖同名）：
  `memfs/`（**必须连里面的 `.git` 一起**）、`conversations/`、`policy.json`、`schedule.json`、`bili-history.json`
- 不要复制：`manifest.json`、`说明.txt`（它们属于存档，不属于 `data`）
- 期望：`<NEW>/data/memfs/<agentId>/memory/MEMORY.md` 存在且非空

**步骤 6 · 隔离 `system.json`（最容易漏，漏了前功尽弃）**

- 做：把 `<NEW>/data/conversations/*/system.json` 移动进 `<NEW>/quarantine-<stamp>/system-json/`
- 期望：每个 `conversations/*/` 下只剩 `messages.jsonl` 和 `conversation.json`
- 为什么：程序启动时会**原样复用**这个文件 —— 它只比对「工具指南版本」和「人格指纹」，不比对记忆。
  而它里面装着两样东西：**常驻记忆正文的副本**（污染在这，就还在）和**压缩摘要**。
  不隔离它，你恢复的文件是对的，但她念的还是旧的。

**步骤 7 · 交回给人启动**

- 做：**不要启动**。输出「可以启动了」，等人双击 `Orb.exe`

**步骤 8 · 启动后验收（应用已在跑之后，agent 可代做）**

三条都要满足：

- **A** `<NEW>/data/conversations/*/system.json` 重新出现了，且修改时间**晚于**本次启动时刻
- **B** 这个新文件里**包含** `<NEW>/data/memfs/<agentId>/memory/MEMORY.md` 里最长的一行 `- ` 开头的正文（取前 40 个字符去比对）
- **C** 如果人提供了「污染特征词」（那段被伪造的话、那个假事实），新文件里**不包含**它

三条全过 → 修好了。任一不过 → 走 A.4。

### A.4 回滚

1. 把 `quarantine-*/system-json/*` 放回各自原来的 `conversations/<id>/` 下
2. 把 `<NEW>/data` 换回步骤 1 的 `orb-rescue-backup-*/data`
3. 报告停在哪儿、哪条验收没过

### A.5 最后要给人看的报告

```
存档：<SNAP>   agentId=<id>   冻结于=<createdAt>   文件数=<n>   校验=<OK/fail>
备份：<rescue-backup 路径>
system.json：已隔离 <k> 个 → <quarantine 路径>
验收：重建=<是/否>   含记忆原文=<是/否>   含污染特征词=<是/否>
结果：<修好 / 停在步骤 X，原因：...>
```

## 附录 B · 同机回档（agent 版）

比 A 短，但**必须人配合**，因为有一步要开界面。

1. **agent**：先把当前状态冻结一份（哪怕它是脏的）—— 那份里面有冻结点之后的全部真实经历，将来可能用得上
2. **人**：点「唤醒记忆」→ 选存档 → 确认
3. **人**：**立刻关掉应用。中间一句话都不要说。**
   （说了，那条回复会带着污染后的上下文写进刚恢复的文件，第二回合就看不出来了）
4. **agent**：把 `data/conversations/*/system.json` 隔离进 `quarantine-<stamp>/`
5. **人**：重开，然后照附录 A 步骤 8 验收

## 附录 C · 存档校验脚本（零依赖）

存成 `<NEW>/verify-archive.mjs`，然后：

```
:: 出厂版自带 electron，可以当 node 用
set ELECTRON_RUN_AS_NODE=1
"<NEW>\runtime\electron\electron.exe" "<NEW>\verify-archive.mjs" "<SNAP>" --deep

:: 本机装了 node 就直接
node verify-archive.mjs "<SNAP>" --deep
```

```js
// verify-archive.mjs —— 按 manifest.json 逐文件核对大小与 sha256
import fs from 'node:fs'
import path from 'node:path'
import crypto from 'node:crypto'

const snap = process.argv[2]
const deep = process.argv.includes('--deep')
if (!snap) { console.error('用法: verify-archive.mjs <存档目录> [--deep]'); process.exit(2) }

let man
try { man = JSON.parse(fs.readFileSync(path.join(snap, 'manifest.json'), 'utf8')) }
// ★ 和 MISSING / SIZE / HASH 一样走 stdout：诊断结论都放一个流里，
//   别让只读 stdout 的执行者漏掉最关键的那一条。
catch { console.log('NO-MANIFEST：这个目录里没有可读的 manifest.json'); process.exit(2) }

const sha = (p) => crypto.createHash('sha256').update(fs.readFileSync(p)).digest('hex')
const rels = Object.keys(man.files)
let missing = 0, sizeBad = 0, hashBad = 0

for (const rel of rels) {
  const full = path.join(snap, rel)
  let st
  try { st = fs.statSync(full) } catch { console.log(`MISSING ${rel}`); missing++; continue }
  if (st.size !== man.files[rel].size) { console.log(`SIZE    ${rel}`); sizeBad++; continue }
  if (deep) {
    const want = String(man.files[rel].sha256).replace(/^sha256:/, '')
    if (sha(full) !== want) { console.log(`HASH    ${rel}`); hashBad++ }
  }
}

const bad = missing + sizeBad + hashBad
console.log(`\nmanifest: agentId=${man?.meta?.agentId ?? '(未记录)'} createdAt=${man.createdAt} 层=${(man.layers || []).join(',')}`)
console.log(`核对 ${rels.length} 个文件：缺 ${missing} / 大小不符 ${sizeBad} / 内容不符 ${hashBad}`)
if (bad === 0) console.log(`OK ${rels.length} files`)
process.exit(bad === 0 ? 0 : 1)
```
