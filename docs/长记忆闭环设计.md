# 长记忆是怎么闭环的

> 这份文档补的是「记忆怎么转起来」——三层结构、每轮怎么进上下文、她怎么写进去、写坏了怎么退回去、上下文爆了怎么办。
> 为什么选这个形态、当初怎么取舍，另有内部定稿，不随仓库公开；本文只讲「闭环怎么转起来」，不重复论证。

一句话：**记忆不是训进权重里的，是一个放在硬盘上、会长大的 git 仓**。每轮开始被读进上下文，每轮结束前后可以被改写；每次改写都留一个 commit，所以写错了能退、删错了能捞、几个月后能考古。

---

## 一、仓里有什么

数据根默认是应用目录下的 `data/`（可用环境变量 `ORB_DATA` 指到别处）。记忆仓在 `data/memfs/<agentId>/`，本身就是一个独立 git 仓：

| 路径 | 是什么 | 怎么进上下文 |
| --- | --- | --- |
| `MEMORY.md` | 「现在确定的她认为重要的事」。四节固定：`关于他` / `关于我自己` / `约好但还没做的` / `索引`。硬上限 4 KB | **每轮全文注入** system prompt |
| `about/*.md` | 分主题的长文（某个人、某段关系、某个项目）。想写多长写多长 | **只注入一行索引**：主题名 + 「什么情况下该打开它」+ 一句预览；要正文就自己 `read_memory` |
| `journal/YYYY-MM.md` | 按月流水账，**只追加不覆盖**。每条带 `t` / `kind` / `tags`，`kind ∈ fact / feel / promise / growth / compact` | **只注入一行索引**，正文靠检索或主动读 |

三层是「常驻 / 按需 / 流水」的分工：

- 4 KB 是刻意压的天花板。`MEMORY.md` 太长会把对话本身挤掉，所以写超了会被工具**拒收**并让她先精简，而不是静默截断。
- 细节不塞常驻区，塞 `about/`；`about/` 的索引行回答「什么时候该翻它」，不回答「里面写了什么」。
- 流水账不参与每轮开销，只保证「发生过的事有个地方查」。

`about/` 的一行索引、以及检索用的倒排索引，都是**宿主当场从文件内容算出来的**（没有额外的索引文件要维护，也就没有「索引和正文不一致」这种故障）。唯一长期存在的是 git 历史本身。

## 二、一轮对话里，记忆怎么流动

`src/brain.mjs` 的 `run()` 定死了顺序，记这条线就够了：

1. **取快照（system prompt）**：`ensureSnapshot()` 把「人格 + `MEMORY.md` 全文 + `about/` 与 `journal/` 的索引行 + 工具指南」渲染成一份文本，连同 `promptHash` / `fileHashes` 存进会话。
   - 已经渲染过就**直接复用**，一个字节都不重算 —— 为了命中 prompt 缓存。
   - 只有三种情况会重渲染：换了人格（`hashPersona` 变）、工具指南版本变了（`GUIDE_VERSION`）、或者这次是压缩后的重建。
2. **预算检查**：估算当前上下文 token，超过 `contextBudgetTokens`（默认 24 000，设置里可滑）就走压缩（见第五节）。
3. **漂移检测**：`snapshot.drift()` 拿快照里记的 `fileHashes` 和仓库当前内容比对。**如果这一轮中途记忆被改过**（比如工具写完又改），差异会以 `<memory_update path="…">正文</memory_update>` 的形式**追加到本轮用户消息的尾部**。
   - 关键点：**冻结的 system prompt 不动**，变动只从尾巴进。这样上下文能变，缓存前缀不会碎。
   - 单块和总量都有字节上限（`memoryUpdateMaxBytes`），超了不是截断，而是让调用方去压缩。
4. **组上下文**：`[system=快照, ...最近的消息]`。
5. **尾部拼装**：本轮用户消息 + 时间行 + 余额行 + 语音状态行 + 漂移块 + **本轮召回块**（`recall.forTurn()` 拿用户这句话去检索记忆仓，取前几条带出处的片段塞进尾部）。
6. **落盘**：只把用户真正说过的话写进 `messages.jsonl`。时间行、余额行、`<memory_update>`、召回块**都不落盘** —— 它们是给这一次推理用的临时外挂，落盘了重开对话就会被当成对话正文渲染出来（2026-10-22 修过一次这个污染）。
7. **回合结束**：`onTurnIdle()`（= `main.mjs` 的 `onLoopIdle`）是**唯一**的回合结束信号，负责这一轮的收尾：补写未落盘的、重建索引、通知面板刷新。

## 三、写入闭环：她怎么把事记下来

她手里有 5 个记忆工具（`src/brain.mjs` 的 `executeTool()`）：

| 工具 | 干什么 | 落到哪 |
| --- | --- | --- |
| `write_memory` | 整篇重写一个文件（`MEMORY.md` 或 `about/x.md`） | 走 4 KB 校验 → 原子写 → git commit |
| `read_memory` | 读某个文件全文 | 只读 |
| `save_topic` | 写 `about/<主题>.md`（主题名会被净化为合法文件名） | 同上，写 `about/` |
| `append_journal` | 往当月流水追加一条（`text` + `kind` + 最多 8 个 `tags`） | `journal/YYYY-MM.md` 末尾，`add -A` 后提交 |
| `search_memory` | 同时搜**记忆仓**和**对话仓**，记忆仓结果排前面 | 只读 |

写入的物理保证（`src/memstore-local.mjs`）：

- **原子写**：先写同目录临时文件，再 `rename` 覆盖 —— 断电不会留半个文件。
- **写即提交**：写完立刻 `git add <path>` + `git commit`，提交信息固定 `mem: <path> @ <iso> (<label>)`。面板要靠这个格式区分「她写的」和「宿主归档的」。
- **没有改动就不提交**：先跑 `git diff --cached --quiet` 判退出码。她经常把同一段重写一遍，此时不该报错，只回一句「内容与已保存的一致」——否则她会以为自己没写进去。这个坑 2026-10-19 真机冒烟栽过。
- **串行化**：所有写操作进同一条 `enqueueWrite` 队列，不会两个工具同时改同一个文件。
- **路径约束**：写出去会校验目标在仓内，防止 `../` 逃逸。

所以「记性」这件事的完整链路是：**她想记 → 调工具 → 落盘 → 提交 → 下一轮它要么在常驻区里、要么在索引行里、要么能被搜到**。没有一步依赖模型「记住」——模型每一轮的记忆都是重新读进来的。

## 四、读回来的三条路

记忆只有被读进上下文才算数，而读法分三档，按「多常用」而不是「多重要」分：

1. **全量**（`MEMORY.md`）：每轮都在，成本固定 4 KB 以内。
2. **索引行**（`about/` + `journal/`）：每轮只花一行，回答「有这么个文件、什么时候值得打开」。
3. **检索**（`search_memory` + 本轮自动召回）：用户这句话驱动，`src/recall.mjs` 建倒排索引 → 按词打分 → 取片段。自动召回的结果拼在本轮尾部，**不进 system prompt**，所以既不影响缓存、也不会被当成长期记忆。

三个工具都在提示里明确了「查不到别直接说不记得，换个具体词再查一次」——因为「索引 + 搜索」这条路本来就是为「几万字塞不进 prompt」准备的。

## 五、上下文爆了怎么办（压缩闭环）

压缩不是丢记忆，是丢**原文的视窗**。

1. 估算 token 超预算 → `compactNow()`。
2. `pickBoundary()` 按 `keepRecentMessages` 切出「可压缩的旧消息」。
3. `summarizeMessages()` 让 LLM 把这批旧消息压成一份摘要。
4. 摘要先写进 `journal/`，`kind='compact'`，附 `tags: [compact, 原因]` —— 写失败只记日志，不中断对话。
5. 重建快照：`快照正文 + "\n\n---\n\n## 更早的对话摘要\n\n" + 摘要`。
6. **`messages.jsonl` 一行都不删**。

第 6 条是这套设计的地基（不变量 I1）：**上下文是派生物**。原文永远在盘上，视窗只是临时看法。所以 `tools/rebuild-context.mjs` 可以从 `messages.jsonl` 重新算出一份上下文；换模型、改预算、压缩策略调参，都不需要「重新聊一遍」。

## 六、五条不变量（为什么这么设计）

| # | 不变量 | 一句话理由 |
| --- | --- | --- |
| I1 | 上下文是派生物（`messages.jsonl` 存全文） | 视窗可以随便丢，原文不能丢 |
| I2 | 只认**已提交**的记忆 | 盘上的内容随时可能写到一半，git 里的是定论 |
| I3 | 会话内 system prompt 字节不变（`promptHash` 断言） | 前缀稳定才命中缓存，省钱也省延迟 |
| I4 | 记忆变更**只从尾部**进（`<memory_update>`） | 既要让新记忆生效，又不能让前缀碎掉 |
| I5 | `onLoopIdle` 是唯一的回合结束信号 | 收尾只有一处，不会两处各写一半 |

I3 和 I4 是一对张力：记忆必须能变，但变了不能打断缓存。解法就是「冻结前缀 + 尾部补丁」——这也是整个项目在 token 经济上最省钱的一个决定。

## 七、能退回去吗

能，因为每次写入都是一个 commit：

- 面板的「历史版本」按提交列表展示，可以看某个文件在某次提交时的样子（`revisionAt()`）。
- `git log` / `git reflog` 直接在 `data/memfs/<agentId>/` 里跑就行，她也能通过工具读历史。
- 误删的文件在旧 commit 里；`archive` 那套「整体搬走而不是 reset」的语义也是为这个服务的。
- 机器迁移：**把 `data/` 整个带走**就带走了记忆（仓、commit、流水账都在里面），不需要导出格式、也没有云端账号。

---

## 八、边界（这版没做什么）

- **不是向量检索**：召回是分词 + 打分 + 片段截取，靠关键词命中。问法换个词可能搜不到，所以提示里才反复教她「换具体词再搜」。
- **不自动总结过去**：compress 只压「这一轮视窗里放不下的旧消息」，不会半夜帮你把这一年写成年鉴。要年鉴得她自己写进 `about/`。
- **4 KB 常驻区是硬的**：想让她永远记得的事太多，就得挑；挑剩下的进 `about/`，靠索引行提醒自己该翻。
- **依赖本机 git**：仓是真的 git 仓，机器上没有 git 就退化成普通文件（出厂包已带 MinGit）。
- **软保护而非加密**：记忆是明文 markdown，`data/` 里还有对话原文。它的隐私靠「文件在你自己机器上」，不靠加密。

---

## 九、可以往哪走

按现有限制推断，不承诺排期：

- 召回换成语义/混合检索（现在是纯词面）。
- `about/` 的索引行由她定期重写（现在只在写文件时更新）。
- 记忆仓按年分段归档，避免 `journal/` 单文件无限长。
- 面板加「记忆健康度」：常驻区利用率、最近一次写入距今多久、孤儿文件检测。
