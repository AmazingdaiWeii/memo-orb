# 第一部分 · 冻结记忆 / 唤醒记忆

## 一、它解决什么问题

一个跑在本地的陪伴型助手，最脆弱的不是模型，是**数据只存在这一台机器上**：

- 硬盘坏了、系统重装了、换电脑了 —— 记忆仓和几千轮对话一起没了；
- 手滑删了 `data/` —— 没有任何一层保护挡得住；
- 想把「她」带到另一台机器上 —— 只能整个目录拷，而拷过去的目录未必能被认回来。

之前的项目里有两层保护，但都盖不住这个场景：

| 已有 | 覆盖范围 | 为什么不解决问题 |
|---|---|---|
| `src/snapshot.mjs` | system prompt 文本 | 冻的是**提示词**，不碰磁盘数据 |
| `src/archive.mjs` | 记忆仓的脏改动 | 只提交记忆仓，对话原文与配置不在范围里 |

所以这次补的是缺的那一层：**把此刻的 `data` 整个冻成一份可以搬走的存档，将来能原样唤回来。**

---

## 二、对用户来说，它是两件事

在「她眼中的你」页面底部，四个等宽的按钮排成一行：

```
[ 现在总结 ]  [ 每天一次 ▾ ]  [ 冻结记忆 ]  [ 唤醒记忆 ]
```

- **冻结记忆**：点一下就存。**不需要确认** —— 它不改变任何现有内容，弹确认只会把「想留住这一刻」变成一道手续。
- **唤醒记忆**：点一下只**列出**已有的存档，选一份之后还要再确认一次。

两者视觉一致，**交互刻意不一致**。原因很直接：冻结是无损的，唤醒是**有损的**（拿旧存档覆盖现在的记忆）。如果两个长得一样、都是一点就执行，用户会把「唤醒」当成「把这些记忆读出来看看」。

另外，状态行右侧有一句小字：**「如果你想要保存此刻的我，就试试冻结记忆吧。」**
它只指向冻结，不解释唤醒 —— 冻结与唤醒是一件事的正反两面，解释第二个等于说废话。

---

## 三、存档里到底有什么

分层存，解冻时可以只恢复其中几层：

| 层 | 内容 | 默认 |
|---|---|---|
| 记忆仓 | `memfs/`，**含 `.git` 历史** | ✅ |
| 对话原文 | `conversations/`（messages.jsonl / system.json） | ✅ |
| 偏好设置 | 放行清单、定时、看过的视频 | ✅ |
| 工作区 | `workspace/`（她落盘的图、视频） | ❌ 不冻 |
| 凭据与登录态 | API Key、B 站 cookie、微信配对 | ❌ **永不冻** |

两个「不冻」是不同的理由：

- **凭据永远不进存档**：存档的用途是放进云盘、拷给别人看、带到另一台机器。API Key 跟着走，等于把密钥交给第三方存储。代价是换机器解冻后要重填 Key、重新扫码 —— 这不是缺陷，是设计。
- **工作区不冻**：那是杂物间（她下载的图、生成的视频），可能几百 MB，而「她」是记忆和对话。不冻它，是为了让「丢云盘」这件事在几十秒内完成。

`memfs` 里的 `.git` **必须一起走**。跳过它，唤回来的就只是一个「当前版本的文件夹」，不是一条能看出「哪天改了什么」的历史 —— 没有历史的记忆仓就是坏仓。

---

## 四、存档是个文件夹，不是一个压缩包

这是一个被认真权衡过的决定。

- **部分损坏时可救**：文件夹形态下，`manifest.json` 能告诉你「187 个文件里坏了 3 个，其余完好」，那 184 个还能用。压缩包里，一段字节坏了整个包就废了，你连里面有什么都不知道。
- **零依赖下自己写 zip 容器是新增一个静默损坏面**。Node 没有内置 zip 写入，ZIP 的本地文件头 / 中央目录 / CRC32 得自己写一百多行，而这几行出错的后果恰好是「存档看起来存好了，其实打不开」。
- **用户能自己接管**：整个存档目录可以直接拖进网盘、拷到 U 盘、扔进 NAS，不需要应用参与。

文件夹唯一的缺点是「可能只拷了一半」。这个缺点由**校验**兜住 —— 唤醒前逐个文件比对指纹，缺哪个就指名说哪个，不会硬盖。

---

## 五、每份存档自带一份 `说明.txt`

给拿到这个文件夹的人（可能是几个月后的自己，也可能是换了台电脑的人）一份初步排障指南：

- 存了什么、没存什么、换机的代价；
- 「唤醒记忆」只认什么（同目录的 `manifest.json`）；
- 它什么时候会**拒绝**执行（缺文件 / 大小不符 / 内容被改过），以及为什么这是故意的；
- 想自己查的时候按什么顺序查。

里面只写**已经实现的行为**。一份说谎的排障指南比没有指南更浪费时间。

## 七、三条不变量（改这个模块的人必须先读）

1. **快照必须能自证**：`manifest.json` 里写全每个文件的 sha256。一个说不出自己完不完整的存档，等于没有存档。
2. **解冻前必须先给「现在」存档**。解冻是破坏性动作；没有后悔药的时光机只是另一种删除。
3. **不用硬链接省空间**。`messages.jsonl` 是追加写，硬链接会让「未来的新内容」顺着 inode 写进「过去的存档」，而且完全无声。宁可多占空间，不可让存档可变。

还有一条工程上的：冻结与唤醒**都必须先等当前回合收口**。半截回合的存档，解冻之后会表现为「她重复一句话的开头」—— 比没有存档更难查。

## 九、已知限制（如实写）

1. **唤醒之后要重开一次软件才生效。** 当前会话的 system prompt 在开窗那一刻就冻结了（会话内字节不变），记忆文件换了，但她上下文里还是旧的。文案里如实写了这一点，没有暗示「立刻生效」。
2. **唤醒没有撤销按钮。** 但它会先自动存一份当前状态，所以「回到唤醒之前」用同一套流程就能做到。
3. **这份出厂版不含 `probe/` 与 `tools/`。** 所以命令行版的存档工具（`tools/data-snapshot-cli.mjs`）只在源码仓里有；出厂版只能用界面上的两个按钮。
4. `helper/lib/main.js` 是**构建产物**，而 `helper-src/src/main.ts` 目前是一份不完整的源（不含印象面板通道）。**不要直接跑 tsdown 重新构建**，否则会把整条通道覆盖掉。

## 十、刻意没做的三件事

- **不做 diff。** 能读 diff 的人不需要这个功能；读不了 diff 的人会因为「左右两边选哪个」而更困惑。更本质的是：一旦界面上出现「旧的和新的」，就等于把「她成长了还是她坏了」的判断权交给一个没有判据的人。全量冻结的语义是单一的 —— 这份存好了，能带走，没有判断题。
- **不做定时自动冻结。** 记忆每轮都在变，但**追加不会丢东西**（记忆仓有 git、对话仓本身是日志）。真正会丢的是整篇覆盖，那是可以精确定位的事件，不需要靠猜时间。
- **不做压缩包导出。** 理由见第四节。

# 第二部分 · 记忆写入改造（`patch_memory` / `memory_batch`）

> 这一部分改的是**她写记忆的方式**，界面上没有任何变化。
> 目的只有一个：让「改一行记忆」不必再走「读全文 → 重抄全文 → 覆盖写」这条最贵的路。

---

## 十一、它解决什么问题

在一份 5MB 的运行日志里按**调用 ID 去重**统计工具执行次数（直接 grep 会把 `running:true/false` 两条回显算两次）：

| 工具 | 次数 | 占比 |
|---|---|---|
| `write_memory` | 18 | 23.4% |
| `write_file` | 16 | 20.8% |
| `read_memory` | 13 | 16.9% |
| `append_journal` | 11 | 14.3% |
| 其它（列目录 / 读文件 / 联网 / 定时） | 20 | 25.6% |
| **记忆类合计** | **42** | **53.8%** |

两个发现：

1. **记忆类占了一半以上的工具调用**，`write_memory` 是最大单项。
2. 更要紧的是：`read_memory` 的目标里约 **92% 是 `MEMORY.md`** —— 而这份文件**每一轮都会被全文注入系统提示**（见 `src/snapshot.mjs`）。也就是说，她在读一份已经在她眼前的内容。

根因是接口形态：`write_memory` 只能**整文件覆盖**。改一行，必须先把全文读进来、再把全文重抄一遍当输出、然后整份覆盖回去。**一次改动 = 两次模型往返 + 一次输出全文 + 一次 git 提交。**

---

## 十二、改成了什么

两个新工具，用户看不到，但她的行为会变：

| 工具 | 作用 |
|---|---|
| `patch_memory` | 给 `old`（文件里现在的原文）+ `new`（改成什么），**宿主负责读、匹配、替换、提交**。一次往返改一处，输出只有改动段 |
| `memory_batch` | 一个回合里**一次**写完几处（journal + 事件本 + 常驻记忆）；全部先预演，任何一处不合法**整批不落盘** |

`write_memory` 保留，但描述改成「只有整份重构时才用」。因为整份重抄的风险不在慢，而在**抄错一个没打算改的字**。

顺带改掉了指南里一句诱导。原文写着「不确定文件里写了什么就用 `read_memory` 看一眼再改」——这句话对懒加载的 `about/*.md` 是对的，对常驻的 `MEMORY.md` 是错的（它已经在上下文里）。现在默认改成用 `patch_memory`。

---

## 十三、为什么没有照搬 PTC

DSH 的 PTC 模式（Programmatic Tool Calling）是「模型写一段程序去批量调用工具，中间结果留在执行环境里」。看起来正对这个场景，但没有采用：

1. **没有运行时。** PTC 依赖 Code Mode SDK 与执行沙箱；本项目是零依赖 Electron，自己实现的成本远大于收益。
2. **与既有安全边界冲突。** 本项目的写文件走白名单 + 弹卡审批，`policy` 里执行能力是明确关掉的。引入「能执行代码的面」等于把这层接回去，还得重新回答「沙箱里写文件要不要弹卡」——要，PTC 的优势立刻打折；不要，就是安全倒退。
3. **收益门槛不够。** PTC 的优势在「单个任务内几十上百次同构操作」，而这里一次改动只有 2~3 个机械步骤，且「先读后写」有数据依赖，并行不起来。

只借了它的一条原则：**机械步骤交给程序，语义判断留给模型。** 读、匹配、替换、提交是机械的；「改哪一句、改成什么」仍然是她的判断。

---

## 十四、与幻觉的关系（这是设计的第一约束）

换成「片段替换」会引入一个新风险：`old` 记错了怎么办？如果失败后静默退化成「整份重写」，就等于**让她凭记忆重构全文**——那正是幻觉进记忆仓最粗的管道。所以这一块专门堵了三条路：

| 风险 | 旧行为 | 现行为 |
|---|---|---|
| `old` 匹配不上 | 整份覆盖，连没打算改的段落也被「她以为的样子」覆盖 | **整体拒绝**，并把盘上**真实的那几行（带行号）**回给她 |
| 同一句话在文件里出现两次 | 静默改错位置 | 拒绝，并列出**每一处的行号** |
| 批量写到一半失败 | 不知道哪几个生效了 | 先全量预演，不合法**整批不落盘**；中途失败明确说明「哪几个已生效」 |

还有三条小的：`old` 短于 4 个字符直接拒绝（两三个字的串必然多处命中）；`patch` 不会凭空创建文件；常驻记忆的 4KB 上限在 patch 路径上同样拦（写前先算改完的大小）。

**没解决的，如实写：**

- **`patch` 不校验事实。** `old` 对得上、位置唯一，写进去的 `new` 仍可能是编的。接口层挡不住这件事。
- **唯一匹配但选错行。** 两段措辞相近，她精确命中了没打算改的那处——会成功且不报错。回执里给了行号，但不保证有人核对。
- **新增一种失败模式。** 以前「记不清原文」也能硬写（写完看起来成功、实际可能改坏），现在会被拒绝。这是把**静默错误**变成**显式失败**，但体感上她会「卡一下」。

## 十六、验证与观测

`probe/memory-patch-unit.mjs`：**29 / 0**。覆盖三块：

- **纯逻辑**：唯一匹配、歧义拒绝、最接近行回填、原子性（第 2 处失败则整体不生效）、删除语义；
- **真 git 仓库**（临时目录）：只产生 1 个提交、歧义时文件字节不变、`expectHash` 乐观锁、`dryRun` 不落盘、`maxBytes` 拦截、不凭空建文件；
- **工具分支**：含「预演失败 → 整批不落盘」，以及指南与版本号一致性。

上线后怎么看效果（不用读懂代码）：

```bash
grep -o "\[brain\] patch_memory\|\[brain\] write_memory\|\[brain\] memory_batch" logs/orb.log | sort | uniq -c
```

| 现象 | 含义 |
|---|---|
| `patch_memory` 出现、`write_memory` 变少 | 改造生效 |
| `patch_memory` 被拒比例高（>30%） | 她在凭记忆猜 `old`，需要调措辞 |
| `write_memory` 反而变多 | 她绕回整份重写了，说明约束不够硬 |

想确认「记忆里有没有塞进编造的内容」，唯一可靠的办法是对照原话看 diff：

```bash
git -C data/memfs/<agentId>/memory log -p -3
```

## 十七、已知限制

1. **`GUIDE_VERSION` 17→18 会让老会话在下一轮重建系统提示**，那一刻提示词缓存失效，首次回复会略慢。这是一次性的。
2. **工具是否真被用起来，接口层保证不了。** 指南与工具描述都写死了「改一两处用 patch」，但模型仍可能不用。只能靠日志观察。
3. **`patch` 只改已存在的文件。** 新建文件仍走 `write_memory` / `save_topic`——这是故意的，避免「我以为这个文件存在」。
4. **验收探针不在出厂包里。** `probe/memory-patch-unit.mjs` 在项目的 `probe/` 目录，与第一部分的说法保持一致（本包不含 `probe/` 与 `tools/`）。想复跑要自己把这两样补回去。
