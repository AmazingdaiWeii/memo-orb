## 1. 结论先行

**用户提供的 key `apikey-20261022120917-ggr7m` 被服务端判定为无效。**

实测（2026-10-22，三组对照）：

| 探测 | 端点 | 鉴权头 | HTTP | 回包 |
|---|---|---|---|---|
| A | `POST /api/v3/tts/create` | `X-Api-Key` | 401 | `{"code":45000010,"message":"Invalid X-Api-Key"}` |
| B | `POST /api/v3/tts/unidirectional` | `X-Api-Key` + `X-Api-Resource-Id` | 401 | `{"header":{"code":45000010,"message":"Invalid X-Api-Key"}}` |
| C（对照） | `POST /api/v3/tts/create` | `X-Api-Key: 00000000-0000-0000-0000-000000000000` | 401 | 同样 `45000010` |

判读要点：

- `45000010` 是**鉴权层**的拒绝，发生在计费与参数校验之前 —— 不是 header 拼错、不是网络、不是资源包问题。
- 用一个格式完全不同的假 key 得到**完全相同**的错误码 ⇒ 服务端不区分「格式不对」与「key 不存在」，因此**不能靠错误码反推 key 的格式**。
- 社区接入教程里同一错误码的成因也是「**控制台代际用错了**」：旧版控制台的凭据打新版端点（只给 `X-Api-Key`）就会报 `45000010: Invalid X-Api-Key`。参考 [Hermes 接入火山豆包语音教程](https://linxic.com/tutorial/hermes-volcengine-voice-plugin/)。
- 该值形如 `apikey-<yyyymmddHHMMSS>-<6位随机>`，其中时间戳恰好等于 2026-10-22 12:09:17。这个形态与官方文档里的 key 示例（占位符，非真实形态）对不上，**疑似某个工具生成的占位符**。属推断，不作结论。

⇒ 两种可能，处置不同：

| 可能 | 判据 | 处置 |
|---|---|---|
| key 是假的/占位符 | 控制台里查不到这个值 | 重新建一把（第 5 节） |
| key 是**旧版控制台**的 | 旧版 `/speech/app` 页面能看到它 | 同时补 AppID + AccessKey（第 2.2 节），或直接用新版 key |

先看第 5 节的「三步」，一分钟就能分清是哪种。

## 2. 三套并存的鉴权体系（这是最容易踩的坑）

火山语音把鉴权改了两次，网上教程三代混在一起，必须按自己 key 的来源选对：

### 2.1 新版控制台 · 单头 `X-Api-Key`（推荐，当前主力）

- Key 获取：https://console.volcengine.com/speech/new/setting/apikeys
- 请求头：`X-Api-Key: <api_key>` + `X-Api-Resource-Id: <资源ID>` + `X-Api-Request-Id: <uuid>`
- 官方明确写了：**旧版控制台后续会下线，建议尽快切到新版获取 API Key**。
- 资源 ID（`X-Api-Resource-Id`）决定调的是哪个能力，写错会 4xxxxx：
  - `volc.service_type.10029` —— 语音合成大模型 2.0（豆包语音合成）
  - `seed-icl-2.0` —— 声音复刻 2.0（本项目 `tts-batch.mjs` 用的就是这个）
  - `volc.seedicl.default` —— 声音复刻 1.0

### 2.2 旧版控制台 · 双头

- 获取页：https://console.volcengine.com/speech/app
- 请求头：`X-Api-App-Key` + `X-Api-Access-Key`
  - ⚠️ 头部名字有历史分歧：豆包语音现行文档写 `X-Api-App-Key`，早期 v3 文档写 `X-Api-App-Id`。本项目 `tts-batch.mjs:68` 用的是 `X-Api-App-Id` —— 走旧版双头时若报 `45000010`，先换成 `X-Api-App-Key` 再试。
- 与 2.1 端点相同，只是鉴权头不同（官方原文：「旧版控制台使用，新版控制台只需要 X-Api-Key 即可」）。

### 2.3 更老的 V1 接口 · Bearer / HMAC

- `POST https://openspeech.bytedance.com/api/v1/tts`（官方标注 not recommended）
- 头：`Authorization: Bearer; <access_token>` —— **注意是分号，不是空格**，这是最常见的复制粘贴错误。
- 或 `HMAC256; access_token=...; mac=...; h=...`
- 需要 appid / access_token / secret_key 三件套，来自控制台「创建应用」。
- 缺 appid 时实测回 `HTTP 500 {"code":3031,"message":"pushing data to async workflow: unable to unmarshal request..."}` —— 这个 500 是**参数反序列化失败**，不代表鉴权过了。

## 3. 端点与参数

### 3.1 音频生成（非流式，最适合批量做旁白）

```
POST https://openspeech.bytedance.com/api/v3/tts/create
X-Api-Key: <key>
Content-Type: application/json
X-Api-Request-Id: <uuid v4>
```

```json
{
  "model": "seed-audio-1.0",
  "text_prompt": "要朗读的文本，单次上限 3000 字符",
  "audio_config": {
    "format": "mp3",            // wav | mp3 | pcm | ogg_opus
    "sample_rate": 24000,
    "speech_rate": 0,           // [-50, 100]，0=原速，10≈1.1×
    "loudness_rate": 0,         // [-50, 100]
    "pitch_rate": 0,            // [-12, 12]
    "enable_subtitle": true     // 要字幕时间戳就开
  },
  "references": [               // 可选：声音复刻时给参考音频
    { "speaker": "<音色ID>" }
  ],
  "watermark": false
}
```

回包：`{ "audio": "<base64>", "duration": .., "original_duration": .., "url": "..", "subtitle": {..} }`

- `original_duration` 是**计费依据**（不是 `duration`）。
- 单次上限 **120 秒**音频 ⇒ 长文本必须切段（本项目 `chunks.json` 就是为此切的 10 段）。

### 3.2 单向流式（项目 `tts-batch.mjs` 在用）

```
POST https://openspeech.bytedance.com/api/v3/tts/unidirectional
X-Api-Resource-Id: seed-icl-2.0
```

body 结构是非流式那套的变体：

```json
{
  "user": { "uid": "orb-video-tts" },
  "req_params": {
    "text": "...",
    "speaker": "<音色ID>",
    "audio_params": { "format": "mp3", "sample_rate": 24000, "bit_rate": 160000 },
    "speech_rate": 5,
    "enable_subtitle": true,
    "additions": "{\"context_texts\":[\"用轻快的语气说\"],\"model_type\":4}"
  }
}
```

回包是 **NDJSON**，逐行：`{"code":0,"data":"<base64 音频块>"}`，结束帧 `{"code":20000000}`。

### 3.3 声音复刻的两个硬点（已踩过，写在 `tts-batch.mjs` 注释里）

1. `X-Api-Resource-Id` 必须 `seed-icl-2.0`；写成 `volc.seedicl.default` 会静默走 1.0。
2. `additions` 里必须带 `"model_type":4`，否则**静默回落到 1.0**，`context_texts` 的情绪指令直接失效、不报错。
3. 情绪走 `additions.context_texts`，**不要**用 `req_params.model` —— 官方明说指定 model 后不支持 context_texts。

## 5. 去拿真 key（三步）

1. 打开 https://console.volcengine.com/speech/new/setting/apikeys （**新版**控制台，不是 `/speech/app`）。
2. 若没开通过「语音合成大模型」，先在 https://console.volcengine.com/speech/service/10007 开通并领免费额度。
3. 点「创建 API Key」，复制出来 —— 形如 `a1b2c3d4-5e6f-4a7b-8c9d-0e1f2a3b4c5d`（UUID v4）。

然后任选其一：

```powershell
# 方式一：写进 local-config.json 的 apiKey 字段（推荐，已 gitignore）
# 方式二：临时用环境变量
$env:VOLC_API_KEY='<真 key>'; node video/tts/tts-verify.mjs
# 方式三：直接命令行传
node video/tts/tts-verify.mjs --key <真 key>
```

**还需要音色 ID（`speaker`）**，这是第二个必填项，跟 key 是两件事：

- 用官方预置音色：控制台「音色库」里复制，形如 `zh_female_shuangkuaisisi_moon_bigtts`（已填在 `local-config.json` 里作占位）。
- 用自己的声音（本项目旁白更像是这条路）：先做**声音复刻**，训练出复刻音色，拿到 `S_xxxxx` 形态的 speaker ID，再用 `seed-icl-2.0` 调。

如果只想要「先出一段能听的音频验证链路」，用预置音色 + `volc.service_type.10029` 最快，不需要复刻。

## 6. 错误码速查

| code | 含义 | 处置 |
|---|---|---|
| `45000010` | `Invalid X-Api-Key` | key 本身无效/这套鉴权不收它。换 key，别改 header |
| `3031`（HTTP 500） | V1 接口请求体 unmarshal 失败 | 多半缺 appid / 字段名不对 |
| `45000000` 段 | 参数类错误 | 看 `message`，常是 speaker 不存在或 text 超长 |
| HTTP 429 | 限流 / 额度耗尽 | 查资源包与 QPS |

排查任何失败都先记下响应头 `X-Tt-Logid`，提工单时报这个。

- 错误码文档：https://docs.volcengine.com/docs/6561/2534853
- 语音合成文档总入口：https://www.volcengine.com/docs/6561/1257584
